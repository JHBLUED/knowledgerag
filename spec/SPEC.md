# KnowledgeRAG 规格文档（SPEC）

> 原则：先定死“做到什么算对”，再让 AI/人去做“怎么做”。
> 本文件是验收的唯一依据，所有 issue 都从它拆出。

## 1. 目标（Goal）

为企业内部文档提供**可溯源、权限受控、脱敏、可评估**的问答服务。

## 2. 非目标（Non-Goals，本期不做）

- 不做多租户 SaaS 平台
- 不做训练 / 微调模型
- 不做通用网页搜索（仅限企业内部文档）

## 3. 用户与场景

- 员工：问制度、流程、FAQ，得到带出处的回答
- 管理员：上传文档、配置权限、查看评估指标

## 4. 功能需求（FR）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR1 | 文档摄入 | 支持 PDF / Word / Markdown；保留标题、章节、元数据（部门、密级、来源、日期） |
| FR2 | 检索 | 向量 + BM25 混合检索，经重排后返回 Top-K 片段及出处 |
| FR3 | 生成 | 回答必须标注引用编号；无匹配时明确说“未找到”，不得编造 |
| FR4 | 权限 | 只检索当前用户所属部门有权限的文档；越权内容不得出现在结果中 |
| FR5 | 脱敏 | 回答中的手机号 / 身份证号 / 银行卡号等 PII 自动脱敏 |
| FR6 | 流式 | `/chat` 支持 SSE 流式返回，逐字输出 |

## 5. 非功能需求（NFR）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR1 | 可评估 | 能对黄金数据集输出召回率 / 忠实度 / 相关性（RAGAS 或 LLM-as-judge） |
| NFR2 | 可观测 | 每次请求可追踪：token 数、耗时、检索到的文档 |
| NFR3 | 安全 | 密钥不入库、不回显、不写日志；有依赖锁定与 CI 门禁 |
| NFR4 | 可部署 | Docker Compose 一键起 |

## 6. 技术约束

- Python ≥ 3.12，依赖用 uv 管理并锁定
- LLM 走 OpenAI 兼容协议，默认 DeepSeek，后续可切模型
- 所有外部配置走环境变量（`.env`）

## 7. 里程碑

| 阶段 | 对应 issue | 交付 |
|---|---|---|
| Week 1 数据层 | ISSUE-002, 003 | 能摄入并检索 100 份真实文档 |
| Week 2 检索层 | ISSUE-004 | 混合检索 + 重排 + 出处 |
| Week 3 生成 + 安全 | ISSUE-005, 006 | 引用溯源 + 流式 + RBAC + 脱敏 |
| Week 4 生产化 | ISSUE-007 | 评估报告 + 可观测 + Docker 部署 |
